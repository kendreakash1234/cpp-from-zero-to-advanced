01What is programming?

00-programming-basics/01-what-is-programming

Programming is the process of solving a problem by designing a precise sequence of instructions and expressing it in a language a computer can execute.

Why does it exist?

A computer is extremely fast and extremely literal. It can perform billions of simple operations per second, but it has no understanding of what you want. Programming is how a person turns an intention ("calculate the average mark") into steps so exact that a machine can carry them out without guessing.

How does it work?

Writing code is only one part of programming. The full activity looks like this:

Understand the problem
↓
Design a solutionthe algorithm
↓
Write the code
↓
Build and run
↓
Testwrong result → debug, then back to writing the code
↓
Maintain and improve

Most of the real work happens in the first two steps and in testing. Typing code is usually the smallest part.

Mental model

Programming is like writing a recipe for a cook who follows every word exactly and never uses common sense. "Add some salt" fails; "add 5 grams of salt" works.

Common mistake

Starting to type code before understanding the problem. The result is code that solves the wrong problem, or that has to be rewritten.

Misconception

"Programming means memorising syntax." Syntax is the easy, searchable part. The hard, valuable part is thinking clearly: breaking a problem down, choosing steps, and checking that the steps are correct.

Quick revision

  • Programming = problem solving + expressing the solution precisely.
  • Computers do exactly what they are told, not what you meant.
  • Understand → design → code → test → debug → maintain.

02What is a program?

00-programming-basics/02-what-is-a-program

A program is a set of instructions, together with the data they work on, that a computer can execute to perform a task.

Why does it exist?

Programming is the activity; a program is its result. Once written, a program can be run again and again, by anyone, without the programmer being present.

How does it work?

People write programs as source code: human-readable text. A processor cannot run text directly; it runs machine code. In C++, a compiler and related tools translate the source into an executable. When the executable is started, the operating system loads it and it runs.

Source codemain.cpp · text
→
Translatecompiler and linker
→
Executablemachine code
→
Runthe OS loads it

The detailed translation steps (preprocessing, compilation, assembly, linking) are covered in Stage 01, topic 03.

Key terminology

TermMeaning
Source codeThe program as text written by a person, such as main.cpp.
ExecutableThe translated file the computer can run.
InputData the program receives, for example from the keyboard or a file.
OutputResults the program produces, for example text on the screen.
Misconception

"The .cpp file is the program the computer runs." The .cpp file is source code. The computer runs the executable produced from it. Changing the source has no effect until you build again.

Quick revision

  • A program = instructions + data, executable by a computer.
  • Source code (text) is translated into an executable (machine code).
  • Edit source → rebuild → run. The old executable does not change by itself.

03What is an algorithm?

00-programming-basics/03-what-is-an-algorithm

An algorithm is a finite sequence of well-defined steps that takes some input and produces a correct output for a problem.

Why does it exist?

An algorithm separates what steps solve the problem from how they are written in a particular language. The same algorithm can be written in C++, Python, or on paper. Getting the algorithm right first means the code only has to express a solution that is already correct.

Properties of an algorithm

PropertyMeaning
InputIt takes zero or more inputs.
OutputIt produces at least one result.
DefinitenessEvery step is precise and unambiguous.
FinitenessIt always finishes after a finite number of steps.
EffectivenessEvery step is simple enough to actually be carried out.

Example: largest of three numbers

1. Read a, b, c
2. Set largest to a
3. If b is greater than largest, set largest to b
4. If c is greater than largest, set largest to c
5. Output largest

Every step is definite, there is no loop that could run forever, and it works for any three numbers, including equal ones.

Common mistake

Vague steps such as "find the biggest one." A person can guess what that means; a computer cannot. Each step must say exactly what to compare and what to store.

Misconception

"An algorithm and a program are the same thing." An algorithm is the language-independent idea. A program is one implementation of it in a specific language.

Quick revision

  • Algorithm = finite, precise steps from input to correct output.
  • Five properties: input, output, definiteness, finiteness, effectiveness.
  • Design the algorithm first; then express it in code.

04Input → Processing → Output

00-programming-basics/04-input-processing-output

The IPO model describes a program as three parts: the data it receives (input), the work it does on that data (processing), and the results it produces (output).

Why does it exist?

Before designing any solution, you need to know what you are given and what you must produce. The IPO model forces those two questions first, and the processing is whatever connects them.

Inputwidth = 5, height = 3
→
Processingarea = width × height
→
Outputarea = 15

Example: area of a rectangle

PartContent
Inputwidth, height
Processingarea = width × height
Outputarea

How it looks in C++ (preview; syntax is taught in Stage 01)

int width{};
int height{};
std::cin >> width >> height;         // input
int area{width * height};           // processing
std::cout << "Area: " << area << '\n';  // output
Common mistake

Assuming input is always valid. Real input can be missing, negative, or not a number at all. Deciding what to do with invalid input is part of processing.

Quick revision

  • Ask first: what do I receive, and what must I produce?
  • Processing is the transformation from input to output.
  • Invalid input must be handled, not ignored.

05Variables as stored state

00-programming-basics/05-variables-and-state

A variable is a named place that holds a value the program can read and change. The state of a program is the set of values held by all its variables at a given moment.

Why does it exist?

Programs work in steps, and later steps need results from earlier ones. Variables remember those results. As the program runs, the values change, and following those changes is how you understand what a program does.

Tracing state: swapping two values

To swap a and b, you need a third variable, because assigning directly would overwrite a value before it is saved.

1. Set temp to a
2. Set a to b
3. Set b to temp
After stepabtemp
Start49—
1494
2994
3944

A table like this is called a trace table. It is one of the most useful tools for checking an algorithm by hand.

Mental model

A variable is a labelled box holding one value at a time. Putting a new value in replaces the old one; the old value is gone unless you saved it somewhere else.

Common mistake

Swapping with just a = b then b = a. After the first step both hold the value of b, and the original a is lost.

Misconception

"A variable holds its whole history." It holds only its current value. State is a snapshot, which is why tracing it step by step matters.

Quick revision

  • Variable = named storage for a value that can change.
  • State = all variable values at one moment.
  • Trace tables make state changes visible.

06Data and operations

00-programming-basics/06-data-and-operations

Data is the information a program works with. Operations are the actions that can be performed on that data. Which operations make sense depends on the kind of data.

Kinds of data

KindExamplesTypical operations
Whole numbers7, −3, 1000add, subtract, multiply, divide, compare
Fractional numbers3.14, −0.5arithmetic, compare
Text"Akash", "hello"join, measure length, compare
True/falsetrue, falseand, or, not

In C++, each kind of data has a type. Types are covered in Stage 01, topics 11–13.

Kinds of operations

CategoryOperators (conceptual)Result
Arithmetic+ − × ÷ remaindera number
Comparison= ≠ < ≤ > ≥true or false
Logicaland, or, nottrue or false
Misconception

""5" and 5 are the same." One is text, the other is a number. Joining text "5" and "3" gives "53"; adding numbers 5 and 3 gives 8. The kind of data decides the meaning of the operation.

Common mistake

Assuming division always gives a fractional result. In many languages, including C++, dividing two whole numbers discards the fractional part: 7 ÷ 2 gives 3. You will see this in Stage 01, topic 18.

Quick revision

  • Data has kinds: whole, fractional, text, true/false.
  • Arithmetic gives numbers; comparison and logic give true/false.
  • The kind of data decides which operations are valid.

07Expressions

00-programming-basics/07-expressions

An expression is a combination of values, variables, and operators that is evaluated to produce a single value.

How does it work?

An expression is evaluated according to operator precedence (which operator is applied first) and, when needed, parentheses. Multiplication and division are applied before addition and subtraction.

The tree shows the order: the deepest operation is evaluated first.

Examples

ExpressionValue (width = 5, height = 3)Kind of result
width * height15number
width > heighttruetrue/false
(width + height) * 216number
Common mistake

Writing a + b / 2 for an average. Division happens first, so this computes a + (b / 2). The average needs parentheses: (a + b) / 2.

Quick revision

  • An expression always produces a value.
  • Precedence decides the order; parentheses override it.
  • When in doubt, add parentheses for clarity.

08Statements

00-programming-basics/08-statements

A statement is a complete instruction that performs an action. Programs are sequences of statements, executed one after another unless the flow is changed.

Expression vs statement

ExpressionStatement
PurposeProduces a valuePerforms an action
Examplewidth * heightarea = width * height
AnalogyA phraseA complete sentence

A statement often contains expressions. In area = width * height, the expression width * height is evaluated, and the statement stores the result.

Sequential execution

Statement 1read input
→
Statement 2calculate
→
Statement 3show result

Order matters. Printing the area before calculating it prints the wrong value.

In C++, most statements end with a semicolon ;. That is covered from Stage 01 onward.

Common mistake

Putting statements in the wrong order, for example using a value before the statement that produces it.

Quick revision

  • Expression produces a value; statement performs an action.
  • Statements run top to bottom by default.
  • Order is part of correctness.

09Conditions

00-programming-basics/09-conditions

A condition is a true/false question that lets a program choose between different paths.

Why does it exist?

Without conditions, a program does the same thing every time. Conditions let it react to its input: a valid or invalid value, a pass or a fail, a positive or a negative number.

Structure

IF condition THEN
    steps when true
ELSE
    steps when false
END IF

Example: grade classification

IF marks ≥ 75 THEN      output "Distinction"
ELSE IF marks ≥ 40 THEN output "Pass"
ELSE                    output "Fail"
END IF

The checks run in order, and the first true one wins. That is why the highest threshold is checked first.

How it looks in C++ (preview; taught in Stage 02)

if (number % 2 == 0) {
    std::cout << "even\n";
} else {
    std::cout << "odd\n";
}
Common mistake

Boundary errors: using > where the rule says "75 or more" (≥). Always test the exact boundary values, such as 74, 75, 39, and 40.

Misconception

"All conditions are checked." In an if / else-if chain, checking stops at the first true condition. Order changes the result.

Quick revision

  • Condition = true/false question that selects a path.
  • In a chain, the first true branch runs; the rest are skipped.
  • Test boundary values on both sides.

10Repetition

00-programming-basics/10-repetitions

Repetition (a loop) runs the same steps multiple times, either a known number of times or while a condition stays true.

Two kinds of loops

KindWhen to useExample
Counter-controlledYou know how many timesPrint the numbers 1 to 10
Condition-controlledYou repeat until something happensAsk again until the input is valid

The four parts of a loop

Trace: sum of 1 to 4

ii ≤ 4?sum after body
1true1
2true3
3true6
4true10
5falseloop ends, sum = 10

How it looks in C++ (preview; taught in Stage 02)

int sum{};
for (int i{1}; i <= n; ++i) {
    sum += i;
}
Common mistake: infinite loop

Forgetting the update step, so the condition never becomes false.

Common mistake: off-by-one

Running one time too many or too few, usually from < versus ≤. Trace the first and last iterations to check.

Quick revision

  • Loop = repeated steps, by count or by condition.
  • Four parts: initialise, check, body, update.
  • Check the first and last iteration for off-by-one errors.

11Functions as reusable logic

00-programming-basics/11-function-as-reusable-logic

A function is a named, reusable block of steps that can receive inputs (parameters) and give back a result (return value).

Why does it exist?

When the same steps are needed in several places, copying them creates duplicated code that must be fixed in many places when something changes. A function writes the steps once and gives them a name that explains their purpose.

Inputswidth = 5, height = 3
→
area(width, height)return width × height
→
Result15

How it looks in C++ (preview; taught in Stage 03)

int area(int width, int height)
{
    return width * height;
}
Mental model

A function is a black box with a clear label: you know what goes in and what comes out, without needing to see inside.

Common mistake

One function doing everything: reading input, calculating, and printing. A function that only calculates is easier to test and reuse.

Quick revision

  • Function = named, reusable steps with inputs and a result.
  • Removes duplication and gives logic a meaningful name.
  • One function, one job.

12Breaking a problem into smaller problems

00-programming-basics/12-decomposition

Decomposition is splitting a large problem into smaller subproblems, each simple enough to solve on its own, so that combining the solutions solves the whole problem.

Why does it exist?

Large problems are hard to hold in your head at once. Smaller pieces can be understood, written, and tested separately. Each piece often becomes a function.

Example: student grade report

This is top-down design, also called stepwise refinement: start with the whole task, then keep breaking each step down until every step is simple and clear.

Common mistake

Splitting too little (one giant block) or too much (tiny pieces that do not mean anything on their own). A good subproblem has one clear purpose and a name you can explain.

Quick revision

  • Decomposition = big problem → smaller, solvable subproblems.
  • Top-down: refine each step until it is simple.
  • Subproblems often become functions.

13Pseudocode

00-programming-basics/13-pseudocode

Pseudocode is a structured, plain-language description of an algorithm, written to be precise for people without following the syntax of any real programming language.

Why does it exist?

It lets you design and check logic without being distracted by syntax. Pseudocode is quick to write, easy to discuss, and translates almost line by line into code.

Common conventions

KeywordMeaning
INPUT / OUTPUTReceive or display data
SET x TO valueStore a value
IF ... THEN ... ELSE ... END IFDecision
WHILE ... DO ... END WHILERepeat while true
FOR i FROM 1 TO n ... END FORRepeat a known number of times

There is no single official standard. What matters is that each line is clear and unambiguous.

Example: average of n valid marks

INPUT n
SET total TO 0
FOR i FROM 1 TO n
    INPUT mark
    WHILE mark < 0 OR mark > 100 DO
        OUTPUT "Enter a mark from 0 to 100"
        INPUT mark
    END WHILE
    SET total TO total + mark
END FOR
OUTPUT total / n
Common mistake

Writing pseudocode that is really vague English ("process the marks"). If a step cannot be turned directly into code, it needs more detail. Note also that this example still divides by zero if n is 0; good pseudocode handles that case too.

Quick revision

  • Pseudocode = precise logic, no language syntax.
  • Use consistent keywords and indentation.
  • Every line should translate directly into code.

15Basic problem-solving review

00-programming-basics/15-programming-basics-project

Every problem in this stage is solved with the same method: understand it, design the steps, check them by hand, then code and test with normal, boundary, and invalid input.

The method

  1. UnderstandWhat is the input? What is the output? What are the rules?
  2. ExamplesWork out 2–3 cases by hand, including edge cases.
  3. DesignDecompose; write pseudocode or draw a flowchart.
  4. TraceRun the design by hand with a trace table.
  5. CodeTranslate the design into C++.
  6. TestNormal, boundary, and invalid input.

Worked example: classify a number

Problem: read a whole number and output whether it is positive, negative, or zero.

INPUT n
IF n > 0 THEN
    OUTPUT "positive"
ELSE IF n < 0 THEN
    OUTPUT "negative"
ELSE
    OUTPUT "zero"
END IF

Test plan

KindInputExpected output
Normal42positive
Normal−7negative
Boundary0zero
Boundary1 and −1positive / negative
InvalidabcAn error message, not a wrong classification
Misconception

"It worked for my example, so it is correct." One passing case proves very little. Boundaries and invalid input are where most bugs hide.

Quick revision

  • Understand → examples → design → trace → code → test.
  • Test normal, boundary, and invalid input every time.
  • Correct design first makes coding the easy part.

Self-test

Answer each question out loud or on paper before opening the answer.

1. What is the difference between an algorithm and a program?

An algorithm is the language-independent sequence of steps. A program is an implementation of an algorithm in a specific language that a computer can execute.

2. Name the five properties of an algorithm.

Input, output, definiteness, finiteness, and effectiveness.

3. Why does swapping two variables need a third one?

Assigning one variable to the other overwrites a value before it is saved. The temporary variable preserves it.

4. What is the value of 2 + 3 × 4, and why?

14. Multiplication has higher precedence than addition, so 3 × 4 is evaluated first.

5. What is the difference between an expression and a statement?

An expression produces a value. A statement performs an action and often contains expressions.

6. In an if / else-if chain, why does order matter?

Only the first true branch runs. If a broader condition is checked first, narrower ones below it are never reached.

7. What are the four parts of a loop?

Initialise, check the condition, run the body, and update.

8. What causes an infinite loop?

A condition that never becomes false, most often because the update step is missing or wrong.

9. Why should a calculation function avoid printing?

A function with one job is easier to test and reuse. Printing ties it to one kind of output.

10. Which three control structures can express any algorithm?

Sequence, selection, and iteration.

11. Which three kinds of input should every test plan include?

Normal, boundary, and invalid input.
